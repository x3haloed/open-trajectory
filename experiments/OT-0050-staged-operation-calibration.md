# OT-0050 — Staged operation-construction calibration

- **Status:** prospectively frozen; unexecuted
- **Evidence class:** public deterministic calibration if promoted
- **Target:** candidate-free representation-escape protocol repair
- **Candidate actor output:** forbidden
- **Hosted model calls:** forbidden
- **Predecessor:** rejected OT-0049

## Frozen prediction and cheapest falsifier

OT-0049 showed that the bounded executable carrier can express a useful new
operation, but one completed consequence packet did not reliably elicit a
compact reusable operation in one fresh synthesis turn. The smallest distinct
repair is staged construction: retain an actor-authored proposal provisionally,
apply it to completed contact, publish only a compact independent residual and
validity receipt, and let a later fresh process revise before controller-owned
commit.

Reject this calibration if any old-carrier proposal is not exposed by completed
residuals, any invalid proposal is admitted, any completed-contact overfit is
not defeated by the scaled holdout, the hidden compact opportunity fails, any
no-credit branch changes its parent, any projection or rollback gate fails, or
the controller reference becomes actor-reachable. Invalidate on input lock,
test, audit, evidence, privacy, or repository-size failure. Candidate or hosted
output invalidates the design.

## Frozen protocol and controls

The calibration exhausts OT-0048's 48 cases and three regimes. The provisional
snapshot carries only parent identity, actor-authored source, and a compact
validation receipt. It remains under 512 bytes. Validation deterministically
applies the proposal to the same eight completed choices and reports validity,
an eight-bit success vector, and error count. It does not derive, search for,
or reveal a replacement.

Four controller-private proposal families prove discrimination: a valid old-
carrier operation, an over-budget operation, a magnitude-specific operation
that fits contact but reverses on the scaled holdout, and a compact reference
operation. Only the reference proves opportunity; none is candidate evidence.
The staged reference revision must restore zero heldout error after initial
discrepancy, exact contradiction, and a distinct later relation. No-credit,
premature-contact-fit, immutable-parent, exact-restore, reverse-order, and
deterministic-replay checks are decisive.

OT-0049 counted Python AST implementation nodes and rejected a 25-byte linear
expression at 36 raw nodes. OT-0050 prospectively counts semantic expression
nodes instead. This interface repair cannot change OT-0049: that linear output
still scores four errors, remains in the old carrier, and the prior disposition
is immutable.

## Promotion and claim limit

Promote only if every case and frozen gate passes from a clean locked commit.
A pass authorizes at most one fresh OT-0051 staged candidate with two fresh
contexts per regime per worker, twelve actor turns total, zero tools, and the
same representation-escape endpoint. It is candidate-free opportunity and
protocol evidence only—not representation escape, developmental transfer,
widened OT-2, integrated development, or OT-3.
