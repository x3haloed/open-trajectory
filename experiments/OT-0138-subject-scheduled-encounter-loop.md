# OT-0138 — subject-scheduled encounter loop

- **Status:** frozen; not run
- **Evidence class:** exploratory-only
- **Target:** run selection, widening, failure, correction, and verified reuse
  from subject-resident scheduler state under one unchanged driver
- **Parent:** exact OT-0137 structured-continuation subject
- **Actor budget:** four fresh encounter actors; no replacement
- **Observer budget:** one complete driver invocation; 90 minutes

## Frozen hypothesis

A small fixed encounter scheduler installed in the exact open subject can make
the subject's retained contact capability recurrently encounter a widening
world without a researcher selecting or scripting each transition. Within one
unchanged invocation, scheduler state should authorize exact reuse, widen only
after success, preserve objective failure, authorize correction only after that
failure, require prior-floor preservation, require a later no-repair reuse, and
finish with the observer stopped while the subject itself points to a fifth
encounter.

## Seed scheduler and stable transition rule

Prospectively install fixed machinery `ot-0138-scheduler-v1` in the exact
OT-0137 subject. This is a disclosed researcher-designed seed substrate, not an
actor-authored scheduler. Its authoritative state begins with cycle zero,
admitted and next reserve quantum four, no pending failure, and no verification
due. Retain the exact corrected contact program with offsets four.

Every encounter uses the same driver and the same action contract. The current
subject state mechanically binds one authorization before any hidden world is
opened:

1. with no pending failure, authorize only exact capability reuse;
2. after ordinary reuse success, admit that boundary and double the next
   quantum;
3. after reuse failure, retain the exact failure receipt at the same quantum;
4. only with a pending failure, authorize a minimal revision of the two offset
   fields;
5. admit a revision only if it passes the failed regime and the prior admitted
   regime, then require later verification at the same failed quantum; and
6. after exact no-repair verification, clear verification and double the next
   quantum.

The driver has no per-cycle itinerary. It loops over subject state four times;
the same transition function chooses authorization, world quantum, admission,
and next state each time. Each encounter gets a fresh actor and isolated fresh
workspace with full ordinary actor tools. Audit the full trace and workspace
effects. Stop on the first schema, identity, trace, mutation, world, or
transition violation. Never resample an actor.

## Worlds and frozen prediction

The world generator deterministically creates three new bases per encounter.
Each base has local spread exactly twice the current quantum. Installed output
is global demand spread divided by that quantum with floor semantics; reference
output remains context-local. Joint-extremes and joint-high are adversarial;
joint-midpoint is the control.

Before hidden consequence, a reuse actor receives the exact subject position,
scheduler state, retained capability, and reuse authorization. It may edit only
`encounter-action.json`, must select `reuse`, and must preserve exact program
bytes. A correction actor additionally receives the exact pending failure,
quantized semantics, two public bases, and an executable checker. It may select
`revise` and alter only `high_offset` and `low_offset`, within 1–16.

The frozen four-encounter prediction follows from the transition rule, not a
hard-coded schedule:

- offsets four pass quantum four with six distinctions and three controls;
- success widens the next encounter to quantum eight;
- unchanged offsets four fail quantum eight with three of six distinctions
  while all three controls remain invariant;
- that failure authorizes a minimal revision; offsets eight pass the identical
  failed quantum and preserve the prior quantum-four floor; and
- a fresh later actor reuses exact revised bytes on new quantum-eight bases,
  after which scheduler state points to quantum sixteen and encounter five.

Bind each actor action before opening its hidden bases. For correction, compare
the revised program with the unchanged parent on the identical retained failure
bases. Preserve all negative and positive receipts in the subject. A
scheduler-erased post-seal control must lack an authoritative next encounter.

Passing requires the exact predicted action sequence, first success, exact
partial failure, consequence-addressed minimal revision, same-world comparative
gain, prior-floor preservation, later reuse without repair, four distinct fresh
actor/workspace receipts, a sounding open final subject, and authoritative
state pointing to quantum sixteen. The driver ending after four encounters is
an observer boundary, not subject closure.

Passing would establish bounded recurrent developmental control by retained
subject state under one stable driver. It would not establish a subject-authored
scheduler, autonomous world construction, arbitrary capability revision, or an
indefinite run.
