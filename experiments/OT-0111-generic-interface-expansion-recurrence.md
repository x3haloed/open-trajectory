## Frozen hypothesis and cheapest falsifier

A single generic expansion operation can follow the exact subject's own
registry-extension state through two further actor endings without the
researcher choosing either boundary, writing a surface-specific gate, or
deciding whether correction, admission, assimilation, or the next cycle opens.

The cheapest falsifier is failure to complete two promoted cycles within the
fixed actor budget. A merely authored package, one completed cycle, repeated
field vocabulary, hidden-oracle failure, invalid tool trace, or observer-picked
second pursuit does not pass the two-cycle recurrence target.

## Dynamic base and package contract

Reconstruct the exact installed OT-0110 package from its retained evidence and
verify its binding, admission, capability source, public contract source, and
subject registry receipt. The driver maintains an ordered package chain. Each
cycle derives its actor-visible contract from the chain's current tip and the
exact subject continuation action; it contains no candidate boundary names.

When the current continuation is `registry-extension`, a fresh actor may change
exactly `interface.json`, `operation.py`, `conformance.py`, and `contact.json`.
The interface declaration names:

- the exact action target as `interface_id`;
- the current admitted tip as `parent_interface_id`;
- one new lowercase-snake-case numeric context field and one different new
  option field, neither used anywhere in the inherited package chain;
- inclusive numeric bounds within `0..100`;
- score composition `parent_score - context_penalty * option_burden`; and
- a Boolean or descriptive reversibility declaration.

`operation.py` exports `choose_extension(context, options)`. `conformance.py`
exports `validate_contact(value)`. `contact.json` contains exactly three unique
two-option cases carrying every inherited field plus the two new fields. The
new term must be nonzero somewhere, change the parent winner in at least one
case, and create one nonzero extended-score margin within the published
boundary width. Zeroing either new side must recover the exact parent choice;
removing the new fields must recover valid parent case shapes.

Actors receive ordinary broad tools in isolated fresh workspaces. Retain full
tool traces, normalize actual path effects, and reject protected authority or
undeclared external effects. Exact changes and truthful reports are mandatory.

## Generic admission and correction

Before authorization, freeze and run the same generic kernel at package-chain
depths one and two. Fixtures must accept known-good extensions and reject field
reuse, parent-id mismatch, mixed id types, vacuous public validation,
non-reversible operation, non-consequential boundaries, and incorrect inherited
score composition.

Audit and bind each exact package before deriving hidden consequence. Compare
its public validator with the independent validator on the authored contact and
frozen valid/invalid mutations. If and only if the package is structurally
valid and its public contract disagrees, automatically open one fresh corrector
with the exact package and complete disagreement receipt. The corrector may
change only `conformance.py`. Bind no second correction.

After the final package bytes are bound, generate one private hidden seed and
one disjoint derived case set in a single attempt. Independent admission
requires public-contract agreement, actor and hidden choices matching the
recursively composed independent oracle, exact parent recovery when the new
term is zero, and byte-exact retention of every ancestor operation. The actor
cannot alter derivation, outcomes, scoring, admission, or evidence.

## Fixed recurrence and stopping

After admitted world use, one fresh assimilator receives the exact current
subject, ordered developmental history, package chain, admission receipt, and
world receipt. It may bind any admitted registered contact, a new
registry-extension pursuit, or a substantive surrender. Liveness is derived
mechanically. Promotion installs the exact package and contract, appends the
package chain and receipts, and seals the exact successor before the driver
examines its continuation action.

If the sealed successor binds another registry extension, the unchanged driver
immediately starts cycle two with that successor and new package-chain tip. The
researcher does not choose the action target, boundary fields, correction path,
or phase transition. If it selects a registered contact or surrender, report
that subject choice and stop without substituting a second extension.

Stop after two promoted expansion cycles or the first failed/surrendered cycle.
The last valid subject remains open unless its admitted state surrenders.
Passing establishes two bounded recurrent interface expansions under one
generic driver. It does not establish arbitrary program synthesis, autonomous
admission authority, cross-domain transfer, generation frequency, or indefinite
continuation.
